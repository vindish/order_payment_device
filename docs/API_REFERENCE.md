# API Reference

Base URL for the aggregate API:

```text
http://localhost:8000/api/v1
```

Interactive OpenAPI docs:

```text
http://localhost:8000/docs
```

## System

Response:

```json

  "service": "Order Payment Device",
  "env": "prod"
```

## Devices

### POST /devices

Auth: Bearer JWT with role `operator` or above.

Request:

```json
{
  "sn": "LOCK-001",
  "name": "测试门锁"
}
```

Response includes `device_secret`. Store it immediately because only its hash is persisted.

```json
{
  "id": 1,
  "sn": "LOCK-001",
  "name": "测试门锁",
  "status": "offline",
  "last_seen_at": null,
  "device_secret": "..."
}
```

### GET /devices

Auth: Bearer JWT with role `operator` or above.

### POST /devices/{sn}/heartbeat

Auth: device headers.

Headers:

```text
X-Device-SN: LOCK-001
X-Device-Token: <device_secret>
```

Marks the device `online` and updates `last_seen_at`.

### POST /devices/events/unlocked?order_id={id}

Auth: device headers.

Marks an order as `DONE`. The order must currently be in a state that can transfer to `DONE`.

### GET /devices/{sn}/shadow

Auth: Bearer JWT.

Returns desired/reported device shadow state.

### PUT /devices/{sn}/shadow

Auth: Bearer JWT with role `operator` or above.

Request:

```json
{
  "desired_state": {
    "lock": "open"
  },
  "reported_state": {
    "battery": 87
  }
}
```

### POST /devices/{sn}/commands

Auth: Bearer JWT with role `operator` or above.

Request:

```json
{
  "command": "unlock",
  "payload": {
    "order_id": 1
  },
  "idempotency_key": "unlock:1"
}
```

Response:

```json
{
  "id": 1,
  "status": "SENT"
}
```

### POST /devices/commands/ack

Auth: device headers.

Request:

```json
{
  "command_id": 1,
  "status": "ACKED",
  "error_message": null
}
```

### POST /devices/telemetry

Auth: device headers.

Request:

```json
{
  "metric": "battery",
  "value": "87.000000",
  "unit": "%",
  "recorded_at": "2026-05-13T12:00:00"

```

Auth: Bearer JWT.

Returns orders for the current user.

## Payments

### POST /payments/callback

No user JWT. Uses payment signature or callback token.

Optional header:

```text
Idempotency-Key: payment-order-1
```

Request:

```json
{
  "order_id": 1,
  "provider": "manual",
  "trade_no": "manual-001",
  "status": "PAID",
  "token": "replace-with-provider-secret",
  "signature": null
}
```

Only `PAID` callbacks are currently supported.

Response:

```json
{
  "msg": "Payment accepted",
  "order_id": 1,
  "status": "PAID"
}
```

Duplicate callbacks for already paid/unlocking/done orders are accepted and ignored.

### POST /payments/callback/wechat

No user JWT. Verifies `Wechatpay-Timestamp`, `Wechatpay-Nonce`, and `Wechatpay-Signature`, then decrypts the `resource` payload with the configured WeChat APIv3 key.

The request body is the raw WeChat notification JSON.

Response:

```json
{
  "code": "SUCCESS",
  "message": "OK"
}
```

Non-success payment events are acknowledged with `{"code":"SUCCESS","message":"ignored"}`.

### POST /payments/callback/alipay

No user JWT. Verifies the Alipay async notification signature from the form-encoded body, then resolves the order by `out_trade_no`.

Response:

```text
success
```

Non-success payment events are acknowledged with `success`.

## Payment Signature Payload

Canonical payload is generated by `backend/app/core/payment_signing.py`:

```json
{
  "order_id": 1,
  "provider": "manual",
  "status": "PAID",
  "trade_no": "manual-001"
}
```

The JSON is serialized with sorted keys and compact separators before HMAC verification. See `backend/app/core/security.py` for the generic signature helper.

## Payment Provider Notes

- Manual callback: `status` must be `PAID`, and the request is accepted by HMAC signature or `PAYMENT_CALLBACK_TOKEN`.
- WeChat callback: `trade_state` must be `SUCCESS`, and `out_trade_no` must map back to an order id.
- Alipay callback: `trade_status` must be `TRADE_SUCCESS` or `TRADE_FINISHED`, and `out_trade_no` must map back to an order id.
